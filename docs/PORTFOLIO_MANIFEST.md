# Манифест проектов `.portfolio.json`

Спецификация манифеста для автоматической синхронизации репозиториев с GitHub в портфолио.

---

## Концепция и фильтрация мусора

Чтобы бэкенд не собирал лишние форки, учебные лабы, черновики или служебные репозитории:

1. **Манифест как пропуск в портфолио**:
   Бэкенд проверяет наличие файла `.portfolio.json` в корне каждого вашего репозитория через `raw.githubusercontent.com`. Если файла нет (404) — репозиторий гарантированно игнорируется.
2. **Автоматическая фильтрация**:
   - Игнорируются форки (`fork: true`).
   - Игнорируются заархивированные репозитории (`archived: true`).
   - Игнорируются служебные репозитории (`.github`, конфиги dotfiles).

---

## Формат файла `.portfolio.json`

Поместите этот файл в корень вашего репозитория:

```json
{
  "category": "prod",
  "role": "Fullstack & Systems Developer (Author)",
  "year": "2024–2026",
  "shortDesc": "Краткое описание в одну строку для карточки каталога.",
  "fullDesc": "Подробное техническое описание архитектуры проекта, его назначения и возможностей...",
  "whyCool": "Главная инженерная фишка проекта (почему это технически интересно)...",
  "highlights": [
    "Ключевая особенность или фича 1",
    "Ключевая особенность или фича 2",
    "Ключевая особенность или фича 3"
  ],
  "techStack": [
    "Rust 2024",
    "Angular 22",
    "Axum",
    "Signals",
    "RxJS"
  ],
  "codeSnippet": {
    "filename": "src/engine/worker.rs",
    "description": "Описание ключевого алгоритма, структуры или пайплайна",
    "code": "pub async fn process_pipeline() -> Result<()> {\n    // Ваш ключевой код\n}"
  },
  "sortOrder": 1
}
```

---

## Допустимые категории (`category`)

| Значение | Название во фронтенде | Назначение |
| :--- | :--- | :--- |
| `"prod"` | Продакшен | Коммерческие проекты, крупные системы, законченные продукты |
| `"pet"` | Pet-проекты | Личные эксперименты, независимые утилиты и сервисы |
| `"arch"` | Архитектура | Монорепозитории, библиотеки компонентов, дизайн-системы |
| `"geek"` | Системные | Low-level разработка, Rust, Linux, сетевые протоколы, FUSE |

---

## Описание полей

| Поле | Тип | Обязательное | Описание |
| :--- | :--- | :---: | :--- |
| `category` | `string` | **Да** | Одна из 4 допустимых категорий (`prod`, `pet`, `arch`, `geek`). |
| `role` | `string` | **Да** | Ваша роль в проекте (например: `Lead Frontend Developer & Architect`). |
| `year` | `string` | **Да** | Годы разработки (например: `2024–2026`). |
| `shortDesc` | `string` | **Да** | Короткое описание для превью-карточки (1–2 предложения). |
| `fullDesc` | `string` | **Да** | Полное техническое описание для модального окна проекта. |
| `whyCool` | `string` | Нет | Инженерная особенность («В чём инженерный интерес»). |
| `highlights` | `string[]` | **Да** | Список маркированных тезисов с ключевыми техническими достижениями. |
| `techStack` | `string[]` | **Да** | Список технологий и библиотек для тегов стека. |
| `codeSnippet` | `object` | Нет | Блок с примером ключевого кода для модального окна. |
| `codeSnippet.filename` | `string` | — | Относительный путь к файлу в репозитории. |
| `codeSnippet.description` | `string` | — | Однострочное описание того, что делает данный фрагмент кода. |
| `codeSnippet.code` | `string` | — | Исходный код сниппета. |
| `sortOrder` | `number` | Нет | Приоритет сортировки в списке (меньше число = выше в списке, по умолчанию `0`). |

---

## Как запустить обновление

1. Добавьте файл `.portfolio.json` в репозиторий и запушьте в GitHub (`main`).
2. Запустите синхронизацию одним из способов:
   * **Через встроенный терминал на сайте:** команда `sync-projects`
   * **Через API эндпоинт:** `POST /api/projects/sync`
   * **Автоматически:** бэкенд периодически сверяет кэш с GitHub API.
